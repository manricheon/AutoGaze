# Borissal 어프로치 해설 (쉬운 버전, 한글)

> **문서 성격**: Borissal의 이론적 배경을 쉬운 언어로 설명하는 **살아있는
> 문서**입니다. 접근 방식이 바뀔 때마다 이 문서를 함께 수정/업데이트합니다.
> 정확한 수치·명령·실험 기록은 각각 `design.md`(설계 근거),
> `reference.md`(사용법·노브), `training.md`(학습 레시피)가 원본이고,
> 이 문서는 "왜 이렇게 만들었는가"를 설명하는 층입니다.
> 마지막 갱신: 2026-07-15.

## 1. 한 줄 요약

**비디오 설명(video description) 파이프라인에 들어가는 비디오 토큰의
개수를 줄이기 위해, "설명에 필요한 정보를 담은 패치만" 골라내는 초경량
선택기(selector)를 만든다.** 비디오 인코더와 LLM은 토큰 수에 비례해(또는
그 이상으로) 비싸지므로, 전체 토큰의 25~50%만 잘 골라도 나머지 연산
전체가 그만큼 싸진다. 선택기 자신은 모바일에서도 돌 만큼 가벼워야 한다
(목표: 클립당 25ms 이내, 표준 연산만 사용).

## 2. 문제 설정

- 비디오 한 클립은 `(T=8, H=24, W=24)` 그리드의 **패치 토큰 4,608개**로
  표현된다 (해상도 384, 패치 16, 프레임 2장씩 묶은 tubelet 단위).
- 선택기는 이 중 `gazing_ratio` 비율(운영 목표 **0.25~0.5**)만 남기고,
  남긴 토큰의 인덱스 목록(`keep_index`, 오름차순)을 출력한다.
- 이 인덱스 규약은 다운스트림 V-JEPA2 계열 인코더의 토큰 순서
  (`idx = t·(H'W') + h·W' + w`)와 정확히 일치해서, 선택 결과가 재배열
  없이 인코더의 위치 임베딩(RoPE)까지 그대로 구동한다.
- 중요한 전제: **정답 라벨이 없다.** 사람 시선 데이터도, "이 패치가
  중요하다"는 어노테이션도 쓰지 않는다. (원본 AutoGaze의
  gazing_labels.json도 사실 사람 시선이 아니라 복원-최적 선택 순서라는
  또 다른 프록시였다 — 프록시만으로 학습하는 것이 이 프로젝트의 전례다.)

## 3. 모델 구조

두 계열이 있고 역할이 다르다.

### 3.1 Borissal v0 / v0.2 — 학습 없는 신호 기반 선택기

"영상에서 눈에 띄는 곳"을 고전적 신호 두 개로 점수화한다:

1. **모션**: 인접 tubelet 간 밝기 차이 `|tub[t] − tub[t−1]|`
   (코덱 residual의 근사). 움직이는 것은 대개 이야기의 주인공이다.
2. **공간 엣지**: 그라디언트 에너지. 텍스트·물체 경계처럼 디테일이
   몰린 곳이다.

두 맵을 tubelet별로 [0,1] 정규화한 뒤 가중합 `S = w·motion +
(1−w)·spatial` 로 합친다 (`w`는 고정값 또는 내용에 따라 자동 결정).
v0.2는 여기에 7가지 원리적 장치(quantile 노이즈 플로어, 전역 예산 할당 +
tubelet별 최소 보장, 지역/전역 점수 블렌드, 코스-투-파인 블록 게이트 등)
를 더해 "노이즈에 예산을 낭비하지 않고, 덩어리로 응집된 선택"을 만든다.

**역할**: (a) 지금 당장 배포 가능한 베이스라인 (현재 최적 설정:
v0.2 + spread 0.25), (b) v1의 입력 특징 뱅크, (c) v1 학습 초반의
커리큘럼 교사(distillation 워밍업).

### 3.2 Borissal v1 — 학습형 선택기 (~122K 파라미터)

- **몸통: TSM 스타일 2D CNN.** 3D 합성곱 대신 2D 합성곱을 쓰되, 채널의
  일부를 시간축으로 한 칸 밀어주는(shift) 공짜 트릭으로 시간 정보를
  섞는다. 모바일 딜리게이트가 좋아하는 표준 연산만 남는다.
- **입력**: v0.2의 신호 맵들(그리드 해상도), 또는 픽셀, 또는 둘 다
  (`input_mode` 스위치 — 어느 쪽이 이기는지는 스케일 실험 대상).
- **전역 문맥: GCNet-lite.** 진단 결과 TSM 스택의 수용영역은 그리드
  ~9×9 칸에 불과한데, 학습 목적함수는 "클립 전체에서 무엇이 고유한가"
  라는 **전역 질문**을 던진다 — 지역만 보는 모델에게 전역 답을
  요구하는 셈. 그래서 1×1 conv 어텐션으로 프레임별/클립별 가중 평균
  문맥을 만들어 마지막 블록 앞에 더해준다 (+8.3K 파라미터, 지연시간
  변화 없음). 변환은 zero-init이라 학습 시작 시점엔 정확히 no-op이다.
- **점수 헤드: cosine 스코어.** 로짓 크기가 구조적으로 유계라 점수
  포화(아래 §5.3)를 원천 차단한다.
- **출력**: 패치별 점수 1개씩. 추론 시엔 v0와 동일한 top-k 선택 경로와
  Selection 규약을 공유한다 (같은 패킹 헬퍼, 같은 테스트).

## 4. 토큰 선택·분배 정책

점수를 매긴 다음 "어디에 몇 개를 쓸 것인가"는 별도의 정책이다.

- **예산 배분**: 기본은 tubelet마다 균등(`uniform`); 에너지에 비례해
  나누는 `proportional`도 있다 (largest-remainder 반올림으로 총 예산을
  정확히 맞춘다).
- **하이브리드 spread (`spread_fraction = s`)**: 예산의 (1−s)는 점수
  순수 top-k(집중), s는 시공간을 균등 버킷으로 나눠 버킷마다 최고
  1개씩(고르게 퍼뜨림)을 뽑는다. 시간축 쿼터를 먼저 보장해 뒷부분
  프레임이 굶지 않게 한다.
  - **이론적 배경**: "골고루 + 중요한 곳 집중"은 원본 AutoGaze의
    멀티스케일 구조가 하던 일이다 — coarse 스케일 3개가 매 프레임
    토큰의 ~26%를 전역 요약용으로 구조적으로 예약한다. Borissal은
    다운스트림 계약상 단일 스케일이므로, 그에 가장 가까운 등가물이
    층화 샘플링 지분이다. 측정상 **s=0.25가 스위트스팟** (모든 평가
    축이 동시에 개선; 단일 클립 근거라 스케일 런 확인 대기 중).
- **블록 게이트 / 응집성**: 설명 태스크엔 흩어진 점 대신 물체 덩어리가
  유리하다. v0.2는 coarse 패스로 유망 블록을 먼저 고르고(2× 용량
  상한으로 예산은 정확히 유지), v1 학습에는 `train_block_size`로 블록
  단위 선택을 걸 수 있다.

## 5. 학습 방식 (v1, 셀프 슈퍼바이즈드)

### 5.1 기본 아이디어

얼려둔(frozen) **V-JEPA 2.1-L teacher**와 그 predictor를 심판으로 쓴다.
teacher는 비디오 전체의 특징(dense)과 선택된 토큰만의 특징(sparse)을
뽑을 수 있고, predictor는 "이 토큰들에서 저 토큰들을 예측"할 수 있다.
선택기의 성적을 사람 라벨 없이 이 심판에게 물어보는 구조다.

### 5.2 핵심 반전 — coverage는 목적이 아니라 제약

처음 목적함수는 자연스러워 보였다: "선택한 토큰으로 나머지 전부를 잘
예측하게 하라"(**coverage**). 그런데 측정 결과 **랜덤 선택이 모든
saliency 설정을 이겼다.** 이건 버그가 아니라 수학적 필연이다 — 전체
복원 목적의 최적해는 시설 배치 문제(facility location)/D-최적 설계와
같아서, **고르게 흩뿌린 격자 + 경계점**이 정답이 된다. 우리가 관측한
산탄(scatter) 편향과 엣지 밴드 드리프트가 정확히 그 최적해다. I-JEPA,
UM-MAE 등의 SSL 문헌도 같은 현상을 독립적으로 보고한다 (흩어진 앵커 =
저수준 보간 지름길).

그래서 목적을 뒤집었다:

- **주 목적 = uniqueness**: "나머지 토큰들로 **선택된 토큰을** 예측하기
  어렵게 하라." 남들이 흉내 못 내는(=정보가 고유한) 토큰을 고르라는 뜻.
  이러면 흩뿌리기가 더 이상 최적해가 아니다.
- **coverage는 바닥 제약(floor)으로 강등**: 랜덤 선택의 coverage를
  실측해서(`--coverage-floor`), 그보다 나빠질 때만 벌점을 준다. "전체
  맥락을 완전히 버리진 마라"는 안전선 역할만 한다.

### 5.3 손실 구성 (losses.py)

| 손실 | 역할 | 근거 |
|---|---|---|
| `uniqueness_reward` | **주 목적** — 선택 토큰의 정보 고유성 최대화 | §5.2의 목적 반전 |
| `predictor_coverage` (floor) | 제약 — 랜덤 기준선 이하로만 벌점 | 산탄 편향 차단 |
| `v0_distill` (워밍업 ~500스텝) | 검증된 v0 saliency에서 출발하는 커리큘럼; 이후 자동 소멸 | StableMoE·HPM (전부-어려운 선택은 랜덤보다 나쁨) |
| `router_z_loss` (1e-3) | 로짓 폭주(점수 포화) 방지 | ST-MoE의 라우터 안정화 |
| `score_entropy` (0.01) | 점수 분포가 한쪽으로 얼어붙는 것 감시/완화 | MoE rich-get-richer 대책 |
| `hardness_rank` (옵션) | 예측-어려움 순위와 점수 순위 정렬 | 실험 노브 |

선택 자체는 이산이라 미분이 안 되므로, **Gumbel 노이즈를 섞은 hard
top-k(순전파) + straight-through 소프트 게이트(역전파)** 로 그라디언트를
흘린다 (τ=2/3 고정, 어닐링 없음 — τ<0.5는 그라디언트 분산 폭주).

### 5.4 점수 포화 문제와 처방

40스텝 만에 엔트로피가 5.0→2.6으로 떨어지고 grad_norm이 0으로 죽는
현상(P2)을 관측했다. 이는 MoE 라우터의 "부익부" 병리와 같은 것으로,
문헌의 처방을 그대로 채택했다: z-loss(ST-MoE), cosine 스코어 헤드
(X-MoE), 고정 τ. 40스텝 A/B로 엔트로피가 붕괴 대신 평균 회귀함을 확인.

### 5.5 RL 단계는 보류 (트리거만 정의)

AdaMAE가 같은 구조(frozen 교사 + 초소형 선택기)를 REINFORCE로 학습해
saliency가 창발함을 보였다. 우리도 같은 경로(leave-one-out 베이스라인)를
구현해 두었지만 **기본 레시피에선 끈다** — 우리의 ST 경로는 실제 목적을
직접 미분하므로 (라벨 모방→RL 2단계가 필요했던 원본 AutoGaze와 다름)
필요조건이 다르다. 재활성화 트리거: 스케일 런에서 엔트로피 붕괴 또는
grad 사망이 그래도 발생할 때만.

### 5.6 등장하는 모델 정리

| 모델 | 역할 | 학습 여부 |
|---|---|---|
| **Borissal v1** (122K) | 선택기 — 유일하게 학습되는 것 | ✅ 학습 |
| **V-JEPA 2.1-L** (+predictor) | 학습 심판 (uniqueness/coverage 계산) | ❄️ frozen |
| **Borissal v0.2** | 입력 특징 + 워밍업 교사 + 배포 베이스라인 | 비학습 |
| **SigLIP2** (384/p16) | **평가 전용** semantic gate — 학습 루프에 절대 안 들어감 (평가 오염 방지) | ❄️ frozen |
| **VideoMAE** (원본 AutoGaze ckpt) | 교차-가족 참고 축 (복원 계열이라 채택 게이트로는 안 씀) | ❄️ frozen |

teacher와 다운스트림 인코더가 같을 필요는 없다 — 그리드 규약만 같으면
선택 메커니즘 검증은 등가라는 것이 확인되어 있다.

## 6. 평가는 세 축, 판정은 semantic이 우선

복원 계열 지표는 §5.2의 이유로 랜덤에게 구조적으로 유리하다. 그래서
설명 태스크와 정렬된 축을 따로 만들었고, 그것이 채택 기준이다:

1. **semantic recall (PRIMARY)** — SigLIP2 어텐션 헤드가 중요하다고 보는
   상위 10% 패치를 선택이 얼마나 회수하는가. saliency가 랜덤을 이기는
   첫 번째 축이다 (설계 시점에 "여기서도 지면 접근 재고"로 사전 등록했던
   알람은 울리지 않았다).
2. **V-JEPA coverage/uniqueness** — 학습 목적이 실제로 학습됐는지의
   일관성 확인.
3. **VideoMAE 복원** — 다른 모델 계열에서 본 참고치 (산탄 편향이 있어
   게이트로는 쓰지 않음).

여기에 시각 덤프(오버레이) 확인을 더하되, 주의: **보기 좋은 선택과
지표가 좋은 선택은 다를 수 있다** (실측 사례 있음). 충돌하면 둘 다
보고하고, 최종 심판은 결국 다운스트림 캡셔너다.

## 7. 자주 나오는 질문

- **왜 그냥 SigLIP2로 학습하지 않나?** 평가 지표로 학습하면 그 지표를
  해킹하는 법을 배운다(평가 오염). SigLIP2는 심판석에만 앉힌다. 학습은
  순수 V-JEPA SSL.
- **frozen predictor를 심판으로 믿어도 되나?** 완전히는 아니다 —
  REAL-X 이론상, 얼린 평가자를 상대로 학습하면 평가자의 분포 밖 편향을
  착취할 수 있다 (2.1 predictor는 ~90% 마스킹으로 학습됐는데 우리는
  15~75%를 남긴다). 그래서 스케일 런 이후 predictor 보정(REAL-X) 및
  독립 평가자와의 격차 감사(EVAL-X)가 후속 항목으로 걸려 있다.
- **선택이 프레임마다 달라져도 되나?** 된다 — 통짜 클립 설명 태스크에선
  tubelet 간 변동이 해롭지 않다 (스트리밍 UI에서만 문제; 의도적으로
  범위 밖).
