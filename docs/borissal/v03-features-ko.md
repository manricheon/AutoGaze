# Borissal v0.3 — 핵심 특징 해설 (한글)

> 대상 독자: v0.3을 쓰거나 평가하려는 사람. "무엇이 왜 들어갔고, 무엇이
> 왜 빠졌는가"를 결과 수치와 함께 한 장으로 설명한다. 정밀한 판정
> 기록은 `design.md`, 설계 계약은 `v03-design.md`, 노브 목록은
> `reference.md` 참조. 기준 성적은 held-out InternVid 16클립,
> 마지막 갱신 2026-07-19.

## 한 줄 요약

v0.3은 **"고전 saliency 아이디어 후보 뱅크(9+4개)를 만들고, 정량
게이트(semantic recall 주 지표)로 조합을 탐색해, 이긴 6개만 채택한"**
비학습 패치 선택기다. 결과: **semantic recall 0.325 → 0.354** (ratio
0.25; ratio 0.5에선 0.560 → 0.577), V-JEPA coverage/uniqueness **동시
개선**, CPU **~22ms/클립**. (참고: 파일럿 규모의 학습형 v1은 아직 이
기준선에 못 미치지만, 그것은 소규모 파일럿과의 비교일 뿐이다 —
공정한 학습형 대비는 스케일 런 이후에 성립한다.)

## 채택된 6가지 특징 (기여 순)

| # | 특징 | 무엇을 하나 | 왜 description에 좋은가 | 단독 기여 |
|---|---|---|---|---|
| 1 | **피크 촉진 융합** (Itti N(·)) | 채널 맵마다 "(최대값 − 국소최대 평균)²" 배율을 tubelet별로 계산해, 피크가 뚜렷한 맵은 승격하고 화면 전체에 발화하는 맵은 강등 | 텍스처가 그라디언트 채널을 범람시키는 순간, 그 채널의 발언권 자체가 줄어든다 — 채널 수준의 자동 노이즈 방어 | 16클립 중 13승 3패, +0.015 |
| 2 | **coherence 텍스처 게이트** | 구조텐서 고유값 비로 "한 방향 결"(반복 무늬·직선 엣지)을 검출해 그라디언트 채널에서 억제. 곱을 먼저 만들고 4×4 블록 평균으로 축소(ds=4)해 60ms→5ms | 벽돌·격자·수풀 같은 배경 텍스처에 낭비되던 예산이 객체로 이동 | 12승 4패, +0.012 |
| 3 | **영역 채널** (region; DoG로 계산) | 다중 스케일 박스블러 차분(DoG)으로 객체 **본체(면)**를 발화시키는 3번째 채널 — "움직임(모션)/윤곽(엣지)/영역"의 세 번째 층. 모션·엣지는 선에서만 발화하지만 균일한 색의 객체 몸통은 둘 다 0이다 | 캡션은 "빨간 셔츠의 남자"처럼 객체 단위 — 실루엣만이 아니라 몸통 패치가 있어야 인식된다 | 9승 7패, +0.010 (gist 최대 +0.02) |
| 4 | **pool 블록 게이트** | coarse 블록 선택을 "1/2 해상도로 파이프라인 재실행" 대신 "fine 점수 블록 평균"으로 — 파이프라인 2회 → 1회 | 품질 무손실 효율화: 16클립 전체에서 선택이 재계산 방식과 **완전 동일**, 지연 −7ms | 0승 0패 16동 (동일), −7ms |
| 5 | **프레임 단위 spatial** (max 집계) | 엣지 신호를 2프레임 평균이 아닌 원본 프레임마다 계산 후 max 집계 — 빠른 움직임의 모션 블러로 반토막 나던 디테일 보존 (게이트는 tubelet 단위 유지로 +6ms에 억제) | 빠르게 움직이는 피사체의 선명한 순간을 잡는다 | 8승 6패 2동, +0.003 (**채택 중 최약 마진 — 스케일 재확인 대상**) |
| 6 | **uniform 할당** (2026-07-19 재판정으로 전환) | 매 tubelet 동일 예산. 개수-무관 지표로 재측정하자 uniform이 ratio 0.5에서 global을 12승-2패로 이기고 uniqueness까지 앞섬 — "global+floor 우위"는 v0.2 신호·예제 클립 시절의 결론이었다 | 넉넉한 예산에선 집중보다 커버리지가 지배; 모바일 export에도 안전(데이터 무관 정책) | global/floor/cap/spread는 제어 노브로 유지 |

계산 순서 요약: luma/tubelet → 모션(frame-diff) + 엣지(프레임 단위,
coherence 게이트) → 패치 풀링 → 노이즈 플로어 → 영역(DoG) 채널 합류 →
피크 촉진 융합(지역/전역 블렌드) → uniform 할당 + pool 블록 게이트 →
top-k → 오름차순 keep_index (V-JEPA 계열에 무재배열 부착).

## 기각된 후보와 이유 (negative results — 전부 off-기본 노브로 남음)

- **motion center-surround** (4승 12패): InternVid엔 카메라 팬이 적어
  "균일 모션 상쇄"가 정보성 모션만 깎았다. 팬 많은 도메인용 노브로 보존.
- **image signature** (8승 7패 + cov/uniq 동시 열화): DoG와 역할이 겹치고
  판별력이 동전 던지기 수준.
- **색 희소성** (체인 위 6승 10패, +7.5ms): 단독으로는 uniqueness 최대
  이득(+0.114)이었으나 체인에선 주 지표가 하락. uniqueness가 필요해지면
  1순위 재시도 후보 (영역 채널 대체로 시도 권장).
- **엔트로피 융합**: 실클립에서 사실상 항등 (이론상 카메라 폴백이
  실데이터에서 발화하지 않음).
- **점수 EMA / 선택 hysteresis**: 시간 안정성은 얻지만 늦게 등장하는
  객체의 recall을 깎아 "recall 비열화" 채택 조건 위반. 스트리밍 UI
  용도로만.
- **할당 상한 2×**: 이 데이터에선 한 번도 발동 안 함 (블록 게이트가
  이미 노출 상한 역할) — 안전 노브.

## 사용법

```python
from autogaze.models.borissal import Borissal, BorissalConfig
model = Borissal(BorissalConfig.v0_3())          # 배포 프리셋
sel = model.select(video, gazing_ratio=0.5)      # 운영 범위 0.25~0.5
# description 파이프라인에 넘길 것: sel.keep_index (오름차순, -1 패딩)
```

ratio 0.5에서 권장 확인 모드: 기본(global) / `spread_fraction=0.25`
(시공간 뼈대 보장 — gist·recon 회복) / uniform(대조용). 도메인 노브:
시네마틱 콘텐츠는 `center_bias`, 팬 많은 영상은
`motion_center_surround` 재고.

## 알려진 한계 / 다음 단계

- 카메라 모션 축은 이 평가셋으로 판정 불가 (팬 부족) — 팬 많은 셋에서
  `gme`/`motion_cs` 재심 필요.
- 프레임 단위 spatial의 마진(+0.003)은 스케일 런에서 재확인.
- 시간 예산 분배는 규칙 기반(global+floor)까지만 탐색됨 — 학습형
  할당(E5, `v03-design.md` §7.5)이 다음 단계.
- v1(학습형)은 아직 v0.3의 풍부해진 입력 뱅크로 재학습되지 않았다.

## v0.4 (2026-07-22): 프레임 수에 강건한 모션

v0.3의 모션(frame-diff)이 **고정 간격(연속 프레임)**이라, 클립을 더 많은
프레임으로 디코드하면 인접 프레임이 비슷해져 움직임 신호가 약해진다
(16f→32f: 0.176→0.115, −35%). 그러면 선택기가 고프레임 입력에서 액션을
덜 잡는다 — "32프레임 다운스트림이 이상하게 나쁨"의 원인. dense(전체 토큰)는
전부 갖고 있어 무관하지만 **선택은 이 신호에 의존**하므로 직접 타격.

**`BorissalConfig.v0_4()` = v0.3 + `motion_diff_stride="auto"`**: diff 간격을
프레임 수에 비례시켜(round(T/16)) 움직임 신호 세기를 프레임 수와 무관하게
일정하게 만든다. 검증: 신호가 8/16/24/32/48프레임에서 ~0.40으로 평탄
(v0.3는 0.60→0.21), 32f action-locus recall 0.770→0.830. **16프레임에선
v0.3와 비트 동일**(auto stride=1)이라 기존 결과 불변, 24프레임 이상만 바뀐다.
v0.3는 동결된 16f 기준선으로 유지, v0.4가 프레임 수 강건한 배포 프리셋.

## v0.5 (2026-07-22): 큐브 응집 + 외형 우선 + 빠른 속도 (V-JEPA/설명 다운스트림)

다운스트림(V-JEPA 2.1-L 인코더 + Qwen3.5-2B 캡셔너 → 외부 LLM QA)에서 발견:
**v0.4(모션 강화)가 v0.3보다 다운스트림 성능이 낮았다** — selector recall은
중립인데. 원인(실측): v0.4가 엣지 강한 패치(정적 객체·글자)를 버리고 모션
패치로 19% 갈아탐. **인코더 자체가 시간 모델(V-JEPA)이면 모션은 중복**이다 —
인코더가 토큰 위치로 움직임을 알아서 추론하니, 선택기는 **외형(객체·글자
정체성)**을 보존해야 한다. 안 뽑힌 외형은 인코더가 지어낼 수 없다.

**v0.5 = v0.3 기반 + 세 가지:**
1. **큐브 응집** (`score_coarsen=2`): 점수를 12×12로 계산해 2배 복원 →
   2×2가 같은 점수라 통째로 뽑혀 조밀한 큐브. 캡셔너가 객체를 더 잘 grounding.
   block gate 대체.
2. **외형 우선** (`motion_weight="auto"` 기본): 클립별 모션/외형 에너지 비율로
   자동 조절(32f 평균 0.34, 정적 클립 0.03) → 모션 낮추고 객체·글자 강조,
   프레임 수·장면에 자동 적응.
3. **그리드 coherence** (`coherence_at_grid=True`): 구조텐서를 픽셀이 아니라
   패치 그리드에서 계산 → 픽셀 곱·업샘플 제거 (선택 IoU 0.923). +
   frame-spatial 끔(`spatial_diff="tubelet"`, 이득 미미).

속도(Mac CPU, 누적): 16f 19.9→10.8ms (45%↓), 32f 40.3→23.0ms (43%↓).
모두 개별 노브라 켜고 끌 수 있다.

**버전 계보**: v0.3(16f 설명 기준선, 동결) · v0.4(프레임-레이트 강건 모션,
action/이미지-인코더용) · v0.5(큐브 응집+외형 우선+빠름, V-JEPA/설명 권장).
단일 배포본: `dist/borissal_v0{3,4,5}.py`. 미완: 실제 V-JEPA+Qwen QA로
v0.5의 외형 우선 선택이 v0.3를 이기는지 확정.

## v0.6 — saliency-v3.1 정제 반영 (2026-07-24, Mac 프록시)

saliency-v3.1(사용자의 다운스트림 검증 best) 7단계와 대조: 12×12→24×24 큐브는
v0.5, 텍스처 억제는 coherence gate(방식만 다름), min-1 floor는 uniform이 이미 커버.
진짜 새것 3개를 v0.6 개별 노브로(전부 기본 OFF → `v0_6()`==`v0_5()`):
1. **정적 가드**(`static_guard`): 모션 ~0인 튜블렛에만 luma Laplacian 엣지 가산 →
   정적 텍스트/문서/정지 피사체 보존. v0.5의 전역 motion_weight 블렌드보다 외과적.
2. **Laplacian 텍스처 게이트**(`laplacian_gate`): R=Laplacian/모션 비율로 억제
   (coherence gate와 다른 메커니즘).
3. **center bias 재검증**(기존 노브).

**프록시 스윕(SigLIP2 recall/gist, held-out 16클립, ratio 0.25):**

| 변형 | recall | gist | vs v0.5 |
|---|---|---|---|
| v0.5 | 0.3425 | 0.8785 | — |
| **v0.6+static** | **0.3541** | **0.8952** | 8W-7L |
| v0.6+laplacian | 0.2990 | 0.8855 | 3W-13L |
| v0.6+center | 0.3130 | 0.8470 | 8W-8L |

- **정적 가드만 프록시 승리**(recall·gist 둘 다↑) — appearance-first 교훈과 정합.
  v0.6 기본후보, CUDA QA로 확정.
- **Laplacian은 recall 회귀**(−0.044) — coherence gate가 이미 텍스처 억제, 겹치면
  과억제. 기본 OFF.
- **center bias 평균 하락** — InternVid 피사체 비중앙. saliency-v3.1 파이프라인에선
  승자이나 데이터/도메인 불일치 → 도메인별 CUDA QA로 재판정, 기본 OFF.

프록시 한계: recall은 v0.4/motion_weight를 오판한 전례·응집 선호. 최종 심판은
borissal 자신의 V-JEPA 2.1-L+Qwen QA. 배포본 `dist/borissal_v06.py`.
